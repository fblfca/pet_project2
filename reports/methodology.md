# Методика эксперимента

## Что предсказываем

Вероятность отмены бронирования на момент его создания. Целевой столбец — `is_canceled`.

Из признаков исключены `reservation_status`, `reservation_status_date`,
`assigned_room_type`, `booking_changes`, `days_in_waiting_list`: их значения
могут быть известны только позднее. Оставшиеся признаки считаем доступными при
создании брони. Для практического применения это допущение нужно проверить в PMS.

До разделения удаляются 31 994 полностью совпадающие строки исходного CSV.
Без уникального ID брони невозможно установить, все ли повторы технические;
это решение важно учитывать при интерпретации метрик.

## Как сравниваем

Эксперименты с восемью моделями выполняются в `notebooks/02_model_experiments.ipynb`.
После выбора победителя `src/pet_project2/experiment.py` повторяет только
финальное обучение и сохраняет модель с её параметрами.

Откладываем 20% данных в тест с сохранением доли отмен. Из обучающей части
берём 8000 строк для сопоставимого по времени сравнения восьми моделей.
Для каждой модели делаем RandomizedSearchCV с двумя наборами параметров и тремя
фолдами. Отдельно сравниваем KFold и StratifiedKFold с одинаковым seed.
Выбор победителя основан на среднем ROC-AUC при StratifiedKFold. Тест не участвует
в подборе параметров. Победителя затем обучаем заново на всей обучающей части.
На тесте также считаем PR-AUC как Average Precision: это помогает оценить,
какой Precision удаётся сохранить при увеличении Recall.

Категории кодируются OneHotEncoder, числа заполняются медианой и масштабируются.
Все преобразования помещены в Pipeline, поэтому на каждом фолде обучаются только
на соответствующей тренировочной части. Редкие категории группируются при
`min_frequency=50`.

## Как трактуем стоимость ошибок

Для учебного сценария предполагаем стоимость пропущенной отмены FN = 200 условных
единиц, ложной тревоги FP = 20. Итоговая стоимость: `200 * FN + 20 * FP`.
Это иллюстрация, а не реальные финансовые показатели отеля. Порог выбирается
на отдельной части train, после чего фиксируется для итоговой оценки на test.
Для отдельного учебного сравнения на той же валидационной части выбирается
порог максимального F1. Оба порога фиксируются перед расчётом на test.

## Ограничения

- Данные относятся только к двум отелям и историческому периоду.
- Простое случайное разделение может переоценивать качество для будущих бронирований;
  в следующем исследовании нужен временной holdout по дате создания брони, которой
  в исходном датасете явно нет.
- Для выбора решения, которое снижает реальные убытки, нужны значения стоимости
  ошибок и проверка доступности признаков в момент прогноза.
- Сравнение дорогих моделей проведено на 8000 строках, поэтому итоговый рейтинг
  может измениться при обучении всех моделей на полном наборе.
